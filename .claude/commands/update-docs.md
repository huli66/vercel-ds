# 精炼总结并更新项目文档

## 执行步骤

1. **获取项目变更上下文**
   - 运行 `git log --oneline -20` 查看最近提交
   - 运行 `git diff HEAD` 查看未提交变更
   - 运行 `git diff HEAD~5 HEAD` 查看最近几次提交的变更内容

2. **读取现有文档**
   - 读取 `docs/README.md`
   - 读取 `docs/PROMPT.md`

3. **读取代码确认当前实现**
   - 查看 `src/` 目录结构，确认实际的组件和模块
   - 对于新功能，读取相关源码确认实现细节（不凭记忆）

4. **更新 README.md**
   - 确保功能描述完整、技术栈准确
   - 架构图/模块说明与实际代码一致
   - 定位：项目技术文档（是什么/为什么）

5. **更新 PROMPT.md**
   - 将新功能作为新阶段添加，或合并到已有阶段
   - 更新一句话版本摘要
   - 定位：从零复现的实施指南（怎么做）

6. **去重与交叉引用**
   - 检查两个文档之间的重复内容
   - README 侧重"是什么/为什么"，PROMPT 侧重"怎么做"
   - 重复内容用交叉引用替代，不大段复制

## 关键规则

- **README 定位**：项目技术文档（架构、模块说明、注意事项、技术栈）
- **PROMPT 定位**：从零复现的实施指南（分阶段提示词，操作步骤）
- **不丢信息**：保留已有的关键内容（如 AI SDK v6 注意事项、API 差异表等）
- **准确性**：新功能描述必须基于实际代码确认，不凭对话记忆
- **精简**：去除过时描述，合并重复内容，保持文档简洁有效
