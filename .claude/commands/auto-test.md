# 自动判断并添加测试用例

## 执行步骤

1. **分析变更**
   - 运行 `git diff HEAD` 查看未提交变更
   - 如果没有未提交变更，运行 `git diff HEAD~1 HEAD` 查看最近一次提交

2. **识别变更类型**
   - 新 React 组件
   - 新 API 路由（`src/app/api/`）
   - 新工具函数/lib（`src/lib/`）
   - 现有组件行为修改
   - 纯样式调整
   - 配置/文档变更

3. **判断是否需要测试**（参考下方判断矩阵）

4. **如需测试，参考现有模式编写**
   - 查看 `tests/` 和 `e2e/` 目录中已有测试文件，遵循相同风格
   - 参考 `tests/setup.ts` 了解测试环境配置

5. **运行测试验证**
   - 执行 `pnpm test:run` 确认测试通过

## 判断矩阵

| 变更类型 | 单元测试 | E2E 测试 |
|---------|---------|---------|
| 新 React 组件 | 是 | 视交互复杂度 |
| 新 API 路由 | 是 | 是 |
| 新工具函数/lib | 是 | 否 |
| 现有组件行为修改 | 更新已有测试 | 更新已有测试 |
| 纯样式调整 | 否 | 否 |
| 配置/文档变更 | 否 | 否 |

## 测试规范

### 单元测试（`tests/` 目录）

- 框架：Vitest + @testing-library/react
- 文件命名：`tests/components/<ComponentName>.test.tsx` 或 `tests/lib/<module>.test.ts`
- Mock 外部依赖（API 调用、第三方库）
- 测试核心逻辑和边界情况

### E2E 测试（`e2e/` 目录）

- 框架：Playwright
- 文件命名：`e2e/<feature>.spec.ts`
- 使用 `page.route()` mock API 响应
- 测试用户交互流程和页面行为

## 输出格式

分析完成后输出：
1. 变更摘要（哪些文件被修改/新增）
2. 判断结果（需要/不需要测试，原因）
3. 如需测试：生成测试文件并运行验证
